这是什么

我给自己做的一套 AI 协作系统，多个 agent 留下的原始记录、以后还要用的结论、技能入口，以及语音转文字、图片文字识别这些服务，都放在同一套能追查出处的约定下。项目里的草稿、源码和产物仍留在各自的正本里，只有以后可能跨项目用到的认识，才提炼成长期笔记。

留下记录和找回结论，分别用 remember 和 recall。换了会话，recall 默认给我命中的摘要，需要时再取全文。服务另有统一的控制入口，可以查看、启停和设置开关，不需要为了关掉一个部件去改它的实现。

结论要留着出处

记忆分原始层和长期层，分别叫 L1、L2。原始层里，事件只能追加，对话镜像可以随摄入更新，附件单独保存。长期层里放用户模型、系统模型、主题知识和跨项目经验。发生事情后先留原始证据，再由 agent 提炼认识，通过命令行写入长期层。它不会定时把全部记录自动整理一遍。

写长期笔记时，正文要引用原始事件，命令还要声明这些引用，缺了引用，或者声明的引用没出现在正文里，写入就会被拒绝。remember 加上长期保存选项，会同时留事件和带引用的笔记。契约只管有没有引用，引用的事件是否真实、结论是否真的被它支持，没有自动检查。

技能只留一份正文

能力库叫 Armory，按 8 个领域组织入口。能力正文只有一份，agent 所在的宿主通过软链接引用它，软链接就是指向那份正文的入口。别的仓库拥有的能力，只登记位置，服务的使用说明由命令行生成，再同步成技能。

登记和启用是两件事，实际启用要看磁盘上的链接，管理程序每次都重新读。撤下链接不会删除正文，归档会保留内容，明确删除才会删掉正文并留下删除记录。现在登记了 369 项，其中 226 项标成 active，实际启用了多少我没有统计。

做到哪了

  • 重构结束了，基础验收里语音转文字、图片文字识别、记忆追加、读取、检索和隔离开关都有通过的记录。
  • 这只是基础验收，不代表全系统都逐项验过。
  • 按难度派活以前做过，后来那个路由实现归档了，现在没有在用，收益也没有在 Theseus 上验证过。
  • 上下文改写还只是手动运行的实验，裁掉原始信息以后自动从记忆里找回的目标还没做到。
